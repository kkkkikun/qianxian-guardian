## 第一阶段 · 读懂比赛（09-22 ~ 09-27）

**09-25 ｜ 赛前调研日。** 比赛官网 SPA 全部文案提取、OctoSense 12 场景指南全文抓取、
官方三大组织（OctoSense-org / octos-org / hagency-org）**23 个仓库**全部下载并深度阅读。
产出 [调研报告](research-report.md)（495 行）：赛制、13 道悬赏题、四维度评审细则、
奖项结构、初赛/复赛/决赛交付清单，全部核实留档。晚上整合队友的《比赛统一理解版》，
补全课程口径的「终端智能层」解释与评审维度表。

**09-26 ~ 09-27 ｜ 机制入门课 + 定题。** 通读官方课程与演示仓库（144KB 讲稿）。
注意到一个关键事实：官方演示项目 octo-weather「行程守护」就是"日历 × 守护"方向——
说明这个方向被官方认可，但也意味着必须做出差异化。
**09-27 定题：「聚会筹办守护」**——那个在朋友群里被推举出来张罗聚会的人，
从"周末聚个饭？"到 AA 收账结束，全是他的心理阴影面积。六问自检全部通过：
上下文困在群聊里、产出是状态操作不是文本、台账算术可代码断言、有主动触发点、
AI 只做规则做不了的理解部分、Case 有完整生命周期。

同日 Python guardian 引擎动工：schema 校验、幂等、规则分诊、OUP 真链路、
状态机、Outbox 事务对账、注入拦截、崩溃补偿，G1–G5 六套冒烟测试全部写出。

## 第二阶段 · 形态抉择与初版（09-28 ~ 10-05）

**09-28 ｜ 31 个快照仓库 git 化。** 外仓快照全部转为 git 基线，漂移可查。

**09-30 ｜ 提交形态定案（A 路线）。** 官方确认 Rinx 含 host-services broker（PR #28），
但商店 script-app 在 card-host 下无 `octos.*` 服务——这意味着「无 AI 也完整可用」
不是可选项，是硬约束。定案：**官方 script-app 为提交主体**，Python guardian 降级为
"场外链路证明"（证明同样的协议在真实 Matrix + 真实 LLM 下成立）。
当日 `octo new` 起包，main.splash 第一版落地，**`hub check PASSED`**。

**10-01 ｜ 对抗性自审机制诞生。** 内环（写代码的 agent）与外环（独立复验的 agent）
分立——内环自报"全绿"从此不再算数，外环真机逐条复验才算。这一天外环当场抓到
三份文档 digest 互相矛盾、按钮触控目标不达 HIG 44pt、对比度未达 WCAG AA 等问题。
铁律成形：**敢说"这条会扣分"，改掉而不是解释掉。**

**10-01 ~ 10-05 ｜ 功能与边界快速补齐。** AA 收账（数字范式探针 7 例）、AI 建议卡
（「✨ AI 生成」+ 一键采纳，模型文本只进文本槽）、回执三档风格 + pref.json 持久化、
agent 自适应提示（AGENT.md + agent-brief.json）、AI 能力可见性三档探测、
「红线」视觉体系定调（暖纸 + 朱砂，35 组色彩映射）。

## 第四阶段 · 决赛冲刺（10-10 ~ 10-13）

决赛评分口径：**第一看创意，第二看 Agentic 完成度（是否 100% agent 可操），
第三看对 OctoSense 的贡献。**

**10-10 ｜ v0.3.0 管家模式——决赛最重要的一天。** 用户看完视频指出：
全程人工点击，没有 agent 驱动能力。当天四片齐发：
状态层收口（全部状态变更走 save() 咽喉）；
**PLAN 单行机器提案协议**（六操作全走白名单 fn，槽位词表归一防编造）；
chat 三视图（我/管家/系统气泡 + 待拍板提案卡）；
**真模型证据**——真实 octos 内核 × MiniMax-M3 返回合规 PLAN，
mock 剧本与真模型双证。当晚经用户提供的代理重建内核（含 octos #2734 修复），
**Rinx 真宿主 e2e 四轮全绿**，MiniMax-M3 真模型 create/reschedule/confirm 全链跑通。
演示视频重剪为"AI 管家实机演示"主线。

**10-11 ｜ v0.4.0 出行保障扩展。** 调研三路（宿主服务/网络 MCP/提醒约束）定边界：
os.calendar 只应答自己、device_calendar 仅 macOS、MCP 被准入明确拒绝、
app 不能自醒——天气改走**内核 skill** 路线（管家回合真调 get_forecast）。
绝对日期地基（Hinnant 历法 2000 天逐日 PASS，抓出 +719468 约定混用 bug）。
提示词规则 6：实时信息必须调工具——首轮模型编造温度的 no-facts 险情被当场修复。
确认自动 ICS、三层提醒（app 行 → Rinx 真发群消息 → bridge 伴生进程真投递入房）。

**10-12 ｜ 密度最高的一天。** v0.8.0 八项进化（调研 22 个同行产品后的落地方案）：
提案卡 diff 化（Cursor 同款审批语义）、拒绝并改写（agent 从被拒中改道）、
全员余额列表、梯度催收四段式（永不公示名单）、守护灯、**沉默留痕**（"考虑过但没说的事"
可回看——全场独有）、三级提醒 + 天气主动复核（≥60% 降水才预警）、
device_calendar 系统日历写链（原生面板物理确认）。管家模型切 Kimi Coding Plan。
v0.9.0 ops 覆盖矩阵：**18 个状态变更全函数级文档化**，100% agent 可操的证据链。
v0.9.2 UI 第二轮重构。
七本剧本视频全录齐（qx-scenario 引擎：边跑断言边录帧），并从"控件树重绘"升级为
**抓真实宿主渲染帧**——用户指出视频远比实际 UI 简陋，当天修复重录。
五本用户视角实机剧本（有什么用/什么场景/怎么用）。

**10-13 ｜ v0.10.x 决赛终版。** WP4 主动回合（agent 到点醒来干活：T-24h 天气复核分级，
不满足阈值就沉默但留痕）；WP5 结案报告卡（四统计 + 状态变迁时间线 + 分享回顾）；
WP3 群智收敛（m.replace 无小程序通路 → 按规划自带降级分支交付：双账号归票实证）。
UI 像素级复刻用户给的 Kimi 设计基准（CJK 字宽 1.44× 实测定标律、
plain View 不绘制实锤、真粗体 CJK 字族、163 处字号重标定）。
main.splash 4766 行单文件拆为 16 部件 + 构建期拼接（字节级零改动实证）。
**回归 40/40，hub check PASSED（contract 1.10.0）**。
2 分钟决赛视频（配音 + 字幕 + 真模型段）上线 B 站。

**10-12 ~ 10-14 ｜ 决赛答辩与材料收口。** 线上决赛：3 分钟应用演示 + 2 分钟
Agent 自动化与技术贡献说明 + 评委问答。官方桌面 shell 源码构建实机运行（系统应用身份）。
上游贡献收口：五个 PR（App-Hub #230 / makepad #125 #124 / Rinx #91 / App-Flow #190）
+ 两个 issue 收口评论，其中 #490 经复核为我们误判，**诚实撤回**——测试留下防疑云。
