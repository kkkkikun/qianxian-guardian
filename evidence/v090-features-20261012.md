## WP1 · ops 覆盖矩阵 + 缺口 op

- **`evidence/ops-coverage.md`**：18 个状态变更函数逐行标注（入口/PLAN op/schema/校验/
  危险级/撤销窗/回归/证据）+ 8 个纯 UI 行理由 + 6 个否定用例。
- **新 op 四个**（全部走 PLAN→校验→拍板→白名单）：`mark_paid`(id+who+amount)、
  `undo`(id, 窗口语义)、`clear`(危险两段拍板)、`export`(可带 id)。
- **AGENT.md v4**：op 全集机器可读表（与 app 内嵌提示词、qx-kernel-turn.py 三处同源）。
- **Rinx×Kimi 真机 e2e**（每 op 独立 fresh Run）：
  - mark_paid 正例：PLAN{id:1,who:阿明,amount:100} → 拍板 → payments.json
    `{persons:[阿明],amounts:[100]}` 落盘 + 对账/自动清零重算回执 ✓
  - mark_paid 否定：who=王五（不在名单）→ 提案卡「⚠ 王五 不在 #1 的参与人名单——拒绝执行」✓
  - export：带 id → 拍板 → evidence/case-1.json 落盘 ✓
  - clear：两段拍板（第一次挂确认、8s 内第二次执行）→ cases.json 移除 ✓
  - undo 正例不可达（8s 窗 < 模型往返延迟）——窗卫语义经拒绝路径在案（诚实边界）
- **真机测出的真 bug 两个，已修**：
  1. 人名分隔符：模型用「、」→ count_people/账本/mark_paid 守卫按英文逗号切（「阿明、阿花」
     成一个人 → mark_paid 误拒）。修：`norm_people_list`（、，;；→逗号+trim）接进
     plan_parse 与 add_person。
  2. **空 else-if 分支中断回调**（clear 回合 hint 停在载入值=回调半途崩）：无 id op 的
     else-if 分支只有注释无语句——填实语句后回调正常。踩坑入档：**空分支=雷**。
  3. 清空两段窗 5s→8s：PLAN 卡路径要读危险提示再二次拍板，5s 实测不够（真机两连拍超窗）。
