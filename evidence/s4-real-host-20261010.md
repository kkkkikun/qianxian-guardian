## 失败定性（客观证据，非我方 app 问题）

官方自带进程级测试 `Rinx-path-backup/tests/standalone_local.rs::standalone_rinx_owns_one_local_runtime_and_stops_only_it`
（不加载我们的 app）在**相同 broker×内核组合**上以**同一错误**失败：

```
called `Result::unwrap()` on an `Err` value: "a peer named 'Rinx 0862de49' already exists"
test standalone_rinx_owns_one_local_runtime_and_stops_only_it ... FAILED
```

复现命令：
```sh
cd repos/Rinx-path-backup
LD_LIBRARY_PATH=~/.local/gosim-libs RUSTFLAGS="-L ~/.local/gosim-libs" \
RINX_TEST_OCTOS_BIN=repos/octos/target/release/octos \
cargo test --offline --test standalone_local -- --nocapture
```

根因链：本机唯一可用的内核二进制（repos/octos 2.0.3-rc.13，2026-09-27 构建）与 Rinx-path-backup
内 vendored app-peers（4fa0f122）的 peer 建立流程不兼容；上游 2026-10-08 的修复
（octos-org/octos #2734「share local runtimes and coordinate workspace peer sessions」）存在但无法本地
构建——github.com TCP 不通（cargo/git 均超时），且完整内核构建依赖 llama-cpp-sys（下载超时）。
vendor/octos-6ad76e5 匹配内核离线构建同样因 crates.io 依赖缺失不可行。

## 已排除的假设（均实测）

- workspace 非 git 仓库导致 clone 失败：初始化 git 后重试，错误不变。
- 残留 peer 目录：全新数据目录 ×3 次复现，首次 turn 即错。
- Rinx 重启恢复 peer：官方测试语义即 restart resume，同样失败。
- 我方 app 请求格式：Rinx 侧仅接受 `{text}` 单参（octos.rs:103 实测+源码），请求已被内核接收。

## 演示变体披露（诚实边界）

Rinx-path-backup（9-26 基线）的 manifest 解析器：
1. 不认识 `agent.instructions` 字段（契约 1.10.0 之前的时代）；
2. 拒绝任何 `agent` 块（"Bundle agent profiles are not supported here"）。

因此 Rinx 演示使用**同源变体副本** `/tmp/qx-demo-bundle`（仅删 manifest 的 `agent` 块，其余字节一致，
hub stamp 重打 digest）。**提交仓的 bundle 保持完整契约**（agent 块 + AGENT.md v3 + model 声明，
hub check PASSED）。变体在 Rinx 内行为与提交包完全一致——管家提示词由 app 自嵌 turn 文本
（build_agent_turn），AGENT.md 仅服务宿主「Ask 牵线」面板（Rinx 本就不注入）。
