## S2 绝对日期地基

- `local_time()`（SCRIPT-API ✓ run：{year month day hour minute second weekday}，weekday 0=Sunday，card-host 为 UTC）+ Hinnant 历法（days_from_civil/civil_from_days，纯整数）→ 槽位词 → 最近未来同名日。
- **历法数学 2000 天逐日抽查 PASS**（首轮实抓 +719468 约定混用 bug——两种纪元约定混用整年 +1970，已修）。
- 北京=UTC+8 跨日修正（UTC hour≥16 → 日期 +1）。
- 不落库：`resolve_slot_date(case)` 即时计算（槽位变则日期变，零 schema 迁移）。

## S3 天气（管家工具路线）

- 管家提示词规则 6：实时信息必须调工具（get_weather/clock），失败明说「暂无法查询实时数据」。
- 实测：MiniMax 真模型在 Rinx 真宿主回合中 `get_forecast` 调用成功，回复真实天气并主动关联守护；工具失败时诚实降级话术验证。
- app 侧 net 代码路径保留边界说明（本机事件泵缺口，平台修复前不启用）。

## S5 日历（ICS + 官方通路边界）

- 确认守护自动生成标准 ICS（VEVENT all-day + SUMMARY/LOCATION/DESCRIPTION，`calendar/qianxian-<id>.ics` 落 jail）——**jail 文件落盘断言 PASS（R-17）**；通用格式可导入任意日历软件。
- all-day 语义规避「发明钟点」（no-facts 红线）。
- device_calendar/gcalendar 完整读写集成因平台硬限制无法在本机验证——边界记档（macOS 上 device_calendar 即为真实现），不写不可验证的代码。

# v0.6.0 增补（2026-10-11 晚）：账目清零闭环 + Evidence Pack（Kimi 建议单 P2/P4）

## 账目清零（口号最后半句）

- **payments.json 独立存储**（[{case_id,person,amount} 三键并行数组]，避开 cases 嵌套数组坑）
- **确定性对账**：`每人应付 = bill_total ÷ 人数`、`已收 = Σ收款`、`差 = 应付-已付`——全部代码计算（详情对账头+逐人行，on_render 只读扁平数组）
- **自动清零**：已收≥总额 → `bill_cleared` 由代码推导写回（手动按钮退役为即时反馈）
- **催收 op `draft_dunning`**：agent 只提议，草稿由 app 确定性组稿（金额/差额零模型参与），填入输入框供人核对发送
- **实机验证**：card-host 全链（记AA 300→加 2 人→对账行「每人 ¥150.00」→收款 阿明 100→「差 ¥50.00」→收款 小红 200→「已收 ¥300.00」+自动清零）；R-22 于 Rinx 真模型实机（模型提 draft_dunning PLAN→拍板→msg_input 草稿 ¥300.00/差 ¥300.00 与状态精确一致；模型首轮只描述意图未出 PLAN，追问后出——对话行为真实可信）

## Evidence Pack（"别信我，验我"）

- **audit 链**：每次状态变更（create/confirm/cancel/reschedule/complete/payment/draft_dunning/bill_auto_cleared）追加 `{UTC+8 时间戳 | actor(user/agent) | action | detail}`——actor 区分人拍板与管家拍板链
- **运行时导出**：详情「导出证据」→ `evidence/case-N.json`（case 快照 + 对账 + 断言规则与输入 + 审计链全量）
- **离线校验** `tools/qx-evidence-check.py`：重算应付/差额、审计收款合计与 paid_total 互洽、时间戳单调、actor 合法、bill_cleared 与 outstanding 一致——**实测 PASS**
- 数字表：main.splash ~3000 行 / 70+ 函数
